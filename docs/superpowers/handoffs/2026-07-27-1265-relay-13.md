## Task 4 — trust-boundary comment wrong for external modules

Same file, **`packages/ai/src/gateway/input-validation.ts:29-32`**:
```ts
/** Compiled `pattern` cache — manifests are static, so each pattern compiles once per process
 *  instead of once per tool call. Patterns come from module manifests, which are trusted code
 *  (a manifest also supplies `execute`), so a manifest author who wanted to burn CPU has far more
 *  direct means than a backtracking regex — this is not a new trust boundary. */
```
This is wrong for **external** modules specifically: a third-party module's declared `pattern`
compiles/runs unconfined and untimed on the **host API event loop**, while that same module's
`execute` is Worker-capped at 30s. That asymmetry IS a new trust boundary for the external case.

**Fix:** correct this comment to state the asymmetry plainly — pattern compilation/matching is
host-event-loop, unconfined, untimed; `execute` is Worker-sandboxed at 30s; for external modules
this is a real (if currently accepted) trust-boundary gap. Reference issue **#1267** (where the
actual confinement/remediation work is tracked). **Do NOT build any sandboxing** — comment-only fix,
explicitly out of scope for this PR.
