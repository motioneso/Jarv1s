## Five things worth calling out explicitly

1. **Exit criterion is UNMET, stated plainly.** The spec's exit criterion
   (`docs/superpowers/specs/2026-07-26-module-self-operation-content-commands.md`, Exit criterion
   section) requires a real dev-instance Playwright UAT run of the three chat-command scenarios
   (add news topic, follow a team, unfollow a source) with no confirmation card, plus a green
   `pnpm verify:foundation`. The gate leg is met (green, see Verification below). The chat-command
   UAT leg is **not** met, for a structural harness reason: no chat-capable seeded AI provider
   exists in the harness today. `tests/uat/specs/self-operation-content-commands.uat.spec.ts` holds
   three `test.fixme` blocks, each with an inline structural reason and a pointer to where the
   behavior is proven instead — backend in `tests/integration/mcp-gateway-self-operation.test.ts`,
   frontend (card-suppression) in `tests/e2e/self-operation-no-confirmation-card.spec.ts` (mocked
   SSE transcript, verified mutation-tight by hand). The real-chat leg still needs a hands-on LAN
   pass. Do not read this as satisfied.
2. **Pattern-anchoring change in the shared gateway validator.** `validateToolInput` (in
   `packages/ai`, changed in `bc506b6a`) now enforces `minLength`/`maxLength`/`pattern` for every
   module's tool input schema, and `pattern` is anchored to the **whole string**, not a substring
   match. This is a real behavior change to a shared gateway chokepoint, not scoped to the
   sports/news tools this PR adds.
3. **External-module blast radius.** Because the enforcement lives in the shared gateway
   validator, it applies to **installed external modules too**, not only built-in ones. Any
   external module whose manifest already declared `minLength`/`maxLength`/`pattern` bounds that
   were previously decorative (parsed but never actually checked) will now have them enforced for
   real.
4. **`packages/settings/src/app-map-tool.ts` is the one in-tree file this flips from decorative to
   enforced.** Its tool input schema declares `maxLength` on `screenId`/`settingId`/`errorCode`/
   `query` (lines 8-11) that were never enforced before this PR — the validator didn't parse those
   keywords pre-`bc506b6a`. Naming it here so it isn't left for a reviewer to find; it's a live
   behavior change outside this PR's nominal scope.
5. **Numeric bounds, `anyOf`, and `additionalProperties` are still UNENFORCED — including on the
   file named in item 4.** `validateToolInput`'s own JSDoc (`input-validation.ts` lines 136-137)
   is explicit that it deliberately does not enforce numeric `minimum`/`maximum`,
   `additionalProperties`, or composition keywords (`oneOf`/`anyOf`/`allOf`/`$ref`) — only string
   `minLength`/`maxLength`/`pattern` went live in this PR. Concretely: `app-map-tool.ts`'s own
   `inputSchema.anyOf` (covering `screenId`/`settingId`/`errorCode`/`query` — the same tool named
   in item 4) is **still decorative, not enforced**. Item 4 above should not be read as "this
   file's whole schema became enforced" — only its `maxLength` string bounds did; its `anyOf` did
   not and does not today.

## Post-QA follow-up (this update)

Re-QA came back green with 4 non-blocking findings; all 4 fixed in this PR rather than deferred
(security tier):

- ESPN dataset fetch (`espn-source.ts`'s `fetchJson`) had no timeout — a hang could pin a pooled
  RLS-scoped DB connection during `followTeam`'s roster check. Added an 8s `AbortSignal.timeout`.
  **This is the one shared fetch chokepoint for all ESPN calls, not just `followTeam`'s roster
  check — it also bounds ordinary read paths (schedules, scores, league team lists).** The
  trade-off is intentional and asymmetric by path: on the write path (`followTeam`) this is a
  fail-closed safety fix — a hang can no longer pin a DB connection, and a timeout rides the
  existing degraded-fallback path straight to reject, no new catch/bypass. On read paths, the same
  8s bound means an ESPN response that would eventually have succeeded past 8s now degrades to an
  empty/stale result instead of waiting for it — a merely slow scoreboard becomes an empty one.
  That degrade-rather-than-hang trade is accepted for reads too, but a reviewer should see it
  named here rather than discover it only in the diff.
- `news.addTopic`'s `label` input schema was missing `maxLength: 80`, a parity gap against REST's
  existing 80-char cap (same class as the sports `teamKey` fix already in this PR).
- `input-validation.ts`'s `compilePattern` catch-block comment falsely claimed "Schema linting is
  the manifest validator's job" — corrected; nothing lints `inputSchema` patterns today. Filed
  #1274 to add that lint, and added a unit test asserting every built-in tool's declared pattern
  compiles under the same anchored `/u` regex `compilePattern` uses.
- The `patternCache` doc comment claimed pattern compilation was "not a new trust boundary"
  without distinguishing built-in from external modules; wrong for external ones specifically,
  since a module's `execute` is Worker-sandboxed/30s-capped but its declared `pattern` compiles
  unconfined on the host event loop. Comment corrected, no sandboxing added (explicitly out of
  scope). Filed #1275 to track that remediation.
