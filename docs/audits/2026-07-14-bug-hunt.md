# Targeted Bug Hunt — 2026-07-14

Targeted (not exhaustive) bug hunt across the full codebase — ~38 packages + 3 apps,
~764 TS/TSX source files / ~147k LOC — for high-signal bug classes: dropped awaits,
RLS/authz gaps, secret leakage, race conditions, null/error paths, resource leaks,
crypto misuse, and injection vectors (SQL / prompt / path).

**Grounded on:** `4c3c51ee` (`origin/main`), verified via a detached read-only worktree
at `/tmp/audit-ground` per the CLAUDE.md grounding discipline. The shared working tree
at `~/Jarv1s` was 37 commits behind `origin/main` at hunt time and was not used as the
source of truth.

**Method:** graph-augmented grep for each bug class across `packages/` and `apps/`,
followed by full-context reads of every hit in the highest-risk surfaces (`db`,
`connectors`, `ai`, `chat` live, `auth`, `news`, `settings` export path, crypto,
route-error handlers). Low-signal pattern matches were triaged out rather than
reported as findings.

**Headline finding:** the codebase is unusually disciplined. AES-256-GCM is
textbook-correct, SQL parameterization is consistent, the canonical route-error
handler scrubs internal details from 500s, and JSON.parse on model output is
uniformly wrapped. **No critical or exploitable bugs were found.** Only minor
issues and code smells surfaced.

## Hunt classes that came up clean (verified, no findings)

- **AES-256-GCM cipher** (`packages/db/src/secret-cipher.ts`) — 12-byte random IV per
  encryption (line 81), auth tag verified on decrypt, keyId-versioned envelopes, legacy
  key fallback only swallows GCM auth failures (line 165) and re-throws structural
  errors. Textbook-correct.
- **Auth queries** (`packages/auth/src/index.ts:165-196`) — proper `$1` parameterization,
  password hashes never selected unnecessarily (`hasPasswordCredential` does an
  `EXISTS` check instead).
- **Floating promises** — every `.then()` chain in `cli-runner`, `chat-session-manager`,
  `news/routes.ts` is correctly awaited or intentionally fire-and-forget with `.catch()`
  + explanatory comment (e.g. `chat-session-manager.ts:849`, `terminal-rpc-client.ts:107`).
- **`handleRouteError`** (`packages/module-sdk/src/route-errors.ts`) — no internal detail
  leakage on 500s; line 105 returns generic "Internal server error" while logging the
  original server-side. Documented as a consolidation from 9 previously-drifted copies.
- **`JSON.parse` on model/external output** — every call site (`ai/structured/generate-structured.ts:143`,
  `commitments/extractor.ts:47`, `connectors/email-extract.ts:347`, and others) is wrapped
  in try/catch with bounded fallbacks. `email-extract.ts:354-358` even has a thoughtful
  comment about truncating *after* the body-containment guard to prevent a leak vector.

## Recommendation

The two genuine findings (#1 race, #2 type cast) are low-severity. Worth a fix if already
touching those files; not worth a dedicated PR. The codebase's testing posture (100+
integration tests across the `test:*` scripts in `package.json`) and the explicit
invariants in `CLAUDE.md` correlate with what this hunt observed: real bugs are scarce.

## Coverage notes

- This was a **targeted** hunt, not a sequential line-by-line read. It covered 100% of
  the codebase for the bug classes listed above, but does not claim every line was read.
- `apps/web` (152 files, frontend) was not deeply inspected — the hunt focused on the
  backend surfaces where the highest-severity bug classes (RLS, secrets, races, crypto)
  concentrate. A separate frontend pass would be a follow-up.
- `cli-runner` concurrency machinery (mutex, admission gates, per-provider locks) was
  inspected at the pattern level but not formally audited; it is complex enough to merit
  its own session if reliability issues surface there.
